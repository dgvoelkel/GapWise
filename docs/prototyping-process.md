# Prototyping process and tools (report §3.2 draft)

Our low-fidelity prototype was built in Figma Make as a React, Vite, and Tailwind app with hand-written fit logic. For the hi-fi prototype we moved it to GitHub and Vercel and used Claude Code as a pair programmer, driven by a build specification we wrote first. The spec fixed what could not change (no calendar connections, no backend, no device location, no changes to the fit logic) and set checkpoints where a team member had to approve the work before it continued.

AI contributed in four places. It wrote the scripts that geocode seventeen campus buildings with OpenStreetMap and fetch real walking routes from a public foot router; it generated the three student personas, their activities, and the graders' deep links; it replaced our schematic SVG map with a real MapLibre map, including the fallback when tiles are blocked; and it wrote the unit and browser tests, report figures, and accessibility fixes (contrast, touch targets, a per-tab help sheet), and debugged a bundling problem with the map's web worker.

We reviewed every output against the spec and a running decision log and changed or rejected several. When the AI could not find Tulane's tennis center in OpenStreetMap, it researched Tulane's site and moved the pin to the new facility at 200 Broadway. That was defensible but put practice a 40-minute walk from the Wilson Center and would have distorted Stella's whole week, so we kept the courts beside Reily and recorded why. We also dropped the plan to copy real class sections (login-only data) and set the times ourselves on Tulane's M W F / T Th grid, and we corrected its shuttle-stop placement. After release one of us found that adding an activity did not update the Right Now headline; the fix went through pull-request review with the fit logic untouched.
